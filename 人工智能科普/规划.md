# 人工智能科普 · 一层层打开黑箱 —— 系列规划

> 状态：**规划稿（第二版，已按作者第一轮反馈修订），待审核**。本文件只做规划；审核通过后再逐集进入“讲解稿 → 动画 → 渲染”。

## 一、系列总览

### 1.1 一句话定位

用大白话加 3Blue1Brown 风格的几何动画，**从“机器怎么学”一直讲到“聊天机器人怎么回答你”**，让完全没有编程、高数基础的人看完后能说清楚：AI 不是魔法，是**数据 + 一个有海量旋钮的函数 + 自动拧旋钮的方法**。

### 1.2 目标观众

| 维度 | 设定 |
|---|---|
| 主要观众 | 初中及以上、对 AI 好奇、每天在用聊天机器人但不知道原理的普通人 |
| 数学门槛 | 只需要**加法、乘法、“坡度/斜率”的直觉**。不出现微积分符号；必要的公式只作为画面角落的“彩蛋卡”，跳过不影响理解 |
| 不面向 | 已经会写神经网络的从业者（他们可以当复习，但我们不为他们牺牲通俗性） |
| 平台 | B站 / 小红书 / 视频号，横屏 16:9 |

### 1.3 规格

- **集数**：**正片 10 集 + 番外 5 集，共 15 集**。正片是一条完整主线，按顺序看；番外各讲一个“同样的原理换个用途”的专题（AI 看图、下棋、多模态、画画、水印），插在正片之间发布，也可以单独看。
- **每集时长**：**5–6 分钟**（与物理科普系列的 5 分钟体量一致，说唱节奏下约 110–130 小节）。全系列约 80–90 分钟。
- **画面**：16:9，1920×1080，30 fps，深色背景、几何化动画（沿用 `物理科普/common/style.py` 的配色与字体）。
- **声音**：**只有说唱（作者用 ACE 生成并对齐）+ 烧录说唱字幕**，没有讲解人声。也就是说：**说唱歌词本身就是旁白**，知识必须写进歌词里；公式、数值、术语卡用画面文字补充。英文术语（Transformer、token、GPT 等）**直接唱英文**（见 2.4）。
- **曲风**：**每集换一种**，由本规划指定（见 1.6），让 15 集听感各不相同，同时每种风格都尽量贴合本集内容。

### 1.4 叙事主线：“打开黑箱”

正片是一个由外到内、再由内到外的旅程；番外是从主线上分出去的岔路：

```
 正片 01     从外面看：AI = 输入 → [黑箱] → 输出，“学习” = 自动拧旋钮
 正片 02–04  打开第一层：黑箱里是什么函数（神经网络），旋钮怎么拧（梯度下降、反向传播）
   └ 番外一  岔路：同样的网络，换一种“看图”的结构（卷积网络）
 正片 05–07  打开第二层：处理语言的黑箱长什么样（词向量 → 注意力 → Transformer）
 正片 08     看它是怎么“长大”的（预训练读遍文本）
   └ 番外二  岔路：没有标准答案时怎么学——强化学习与下棋（为第 09 集铺垫）
 正片 09     后训练：从续写机器变成助手
 正片 10     合上黑箱，回到外面：它能做什么、不能做什么、我们还没看懂什么
   └ 番外三  图片、声音也变成 token：多模态
   └ 番外四  反过来生成图片：扩散模型
   └ 番外五  怎么认出 AI 写的字：文本水印
```

**贯穿全系列的三个“锚点”**（每集都会回扣，保证观众有连续感）：

1. **旋钮面板**：第 1 集只有 2 个旋钮（直线的斜率和截距）→ 第 2 集 13,002 个（手写数字网络）→ 第 7 集 1750 亿个（GPT-3）。旋钮计数器是全系列的固定 UI 元素，数字越滚越大；番外里它也一直在，提醒观众“还是那套旋钮 + 下山”。
2. **一句贯穿正片的提问**：「床前明月光，疑是地上__」。第 1 集它是黑箱外面的一个问题；第 5 集它被切成 token；第 6 集里“霜”在看“明月光”；第 7 集模型给出“霜”的概率；第 10 集我们完整追踪这一个字从输入到输出的全部旅程。（第 10 集同时说明：这一句模型多半是“背过”的，再换一个从没见过的问题看它怎么泛化。）番外五再用它一次：这句话的下一个字几乎只能是“霜”，水印藏不进去。
3. **固定副歌尾句（系列标签）**：每集副歌最后一句落在「**一层一层，把黑箱打开**」上，第 10 集作为正片的收尾句。

### 1.5 全系列配色语言（每集统一，观众形成条件反射）

| 颜色 | 含义 |
|---|---|
| 蓝 `C_BLUE` | 输入 / 数据 / token |
| 黄 `C_YELLOW` | 参数 / 权重 / 旋钮 |

## 二、说唱与画面的总体方案

### 2.1 每集的段落结构模板（以 88 BPM、约 5.5 分钟为例）

一个小节（4 拍）时长 = 240 / BPM 秒；88 BPM 时约 2.73 秒。

| 段落 | 小节数 | 作用 | 画面 |
|---|---|---|---|
| 前奏 Intro | 4 | 纯伴奏 | 片头卡：系列名 + 本集标题 + 旋钮计数器 |
| 主歌一 Verse 1 | 16 | 提出本集的核心问题、回扣上一集 | 第一章 |
| 副歌 Hook | 8 | 本集一句话结论，结尾落在系列标签句 | 本集“标志性画面”的简化版 |
| 主歌二 Verse 2 | 16 | 核心机制 | 第二章 |
| **器乐间奏** | 4 | **不唱，给复杂动画留呼吸** | 关键动画完整演示一遍 |
| 副歌 Hook | 8 | 重复 | 同上，叠加新信息 |
| 主歌三 Verse 3 | 16 | 深入 / 真实规模 | 第三章 |
| 桥段 Bridge | 8 | 放慢、降密度，唱出本集的“顿悟句” | 全屏只留一个画面 |
| 主歌四 Verse 4 | 16 | 局限 / 常见误解 / 证据 | 第四章 |
| **器乐间奏** | 4 | 不唱 | 本集要点卡逐条出现 |
| 副歌 Hook | 8 | 最后一遍 | |
| 尾声 Outro | 8 | 回顾 + 下集预告（用一个问句收尾） | 片尾卡 + 下一集的“悬念画面” |
| **合计** | **约 120** | 88 BPM 下约 5:27 | |

BPM 较快的集（100 BPM 以上）可把主歌加到 20 小节或增加一段主歌，BPM 较慢的集（80–84）可以减少一段器乐间奏，让总时长仍落在 5–6 分钟。每集的准确小节数在讲解稿的小节表里定死。

### 2.2 字幕可读性红线（最重要的一条技术约束）

物理科普系列按 **4.6 字/秒** 估算舒适阅读速度（见 `common/style.py` 的 `CHARS_PER_SEC`）。说唱时字幕跟着音乐走，没法自动延长停留时间，所以：

- **每小节字数上限 ≈ 4.6 × 240 / BPM**。承载新知识的歌词再打八折左右，**一句歌词 = 一小节，或两小节一句**：

  | BPM | 每小节时长 | 字数上限 | 承载知识时建议 |
  |---|---|---|---|
  | 80 | 3.0 s | 13.8 | 9–12 字 |
  | 88–90 | 2.7 s | 12.5 | 8–11 字 |
  | 96–102 | 2.4 s | 11.3 | 7–10 字 |
  | 半拍感 70–71（trap / drill） | 3.4 s（按半拍小节） | 15.8 | 9–12 字，按半拍写 |

- **英文单词的“阅读字数”**：一个短词（token、key、GPT）按 1 个汉字算，长词（Transformer、softmax、embedding）按 2 个汉字算。
- **快嘴段（flow 炫技）只放在不承载新知识的句子上**，例如副歌后半句、尾声的回顾句。
- 第 6 集（trap 140）和番外五（drill 142）**必须按半拍感写词**，否则字幕根本读不过来。
- 每条字幕至多两行，每行不超过 `SUB_MAX_CHARS`（26）字。

### 2.3 歌词与画面的分工

- **歌词负责直觉和结论**：“往下坡迈一步”“越对得上，注意越多”。
- **画面负责公式、数值、术语**：例如 `softmax(QKᵀ/√d)·V` 只出现在画面彩蛋卡上，歌词里不念公式。
- **歌词不为押韵牺牲准确性**：每集讲解稿里的“事实核查表”同时核对歌词和画面文字。押不上就换说法，不换事实。

### 2.4 交给 ACE 的“演唱稿”与烧进画面的“字幕稿”分开写

每集讲解稿里每句歌词写两份：

| | 演唱稿（喂给 ACE） | 字幕稿（烧进画面 / SRT） |
|---|---|---|
| 数字 | 写汉字：「一千七百五十亿」「一万三千零二」 | 写阿拉伯数字：「1750亿」「13,002」 |
| 英文术语 | **唱英文**，按下面的发音表写法写进歌词 | 原样显示英文 |
| 段落标签 | 按 ACE 的歌词格式标注 `[verse]` `[chorus]` `[bridge]` 等 | 不显示 |
| 标点 | 按换气断句 | 按阅读断句 |

**英文术语唱英文（作者已确认）**。为了让 ACE 唱得稳，约定：

- **缩写按字母唱**时，演唱稿里用空格隔开字母，例如 `G P T`、`R L H F`、`S F T`、`D P O`、`V I T`；字幕稿照常写 `GPT`、`RLHF`、`ViT`。
- **当单词唱**的：Transformer、token、Query、Key、Value、softmax、ReLU（唱作 “re-lu”）、Adam、AlphaGo、CLIP（唱作 “clip”）、Whisper、U-Net（唱作 “U net”）、ImageNet、MNIST（唱作 “em-nist”）、prompt。
- 英文词尽量放在**重拍上或句尾**，音节数要算进 flow 里（Transformer 是 3 个音节，token 是 2 个）。英文词也可以参与押韵，但主韵仍以中文韵脚为准。
- 每集讲解稿附一张“发音表”，列出本集所有英文词及唱法；ACE 唱错时，作者可以只改演唱稿里的写法（例如拆音节），不动字幕稿。

风格提示词建议包含：`chinese rap, hip-hop` + 本集曲风（见 1.6）+ BPM + 人声类型。曲风每集换，但**建议全系列固定同一种人声音色**，像固定的主讲人；是否固定由作者决定。

### 2.5 对齐工作流：BPM 小节网格（作者已确认）

物理科普的 `self.say()` 是“按阅读时间推进字幕”。这次是音乐决定时间，采用**先定小节表、所有东西对齐到 BPM 网格**的方式：

1. **讲解稿阶段定小节表**：每集确定 BPM、前奏小节数和每个段落的起止小节，每句歌词落在哪一小节（或哪两小节）。小节表是动画和说唱共同遵守的时间契约，格式如下：

   | 小节 | 段落 | 起始时间 | 演唱稿 | 字幕稿 | 画面事件 |
   |---|---|---|---|---|---|
   | 1–4 | 前奏 | 0:00.00 | （无） | （无） | 片头卡 |
   | 5 | 主歌一 | 0:10.91 | 床前明月光，疑是地上什么 | 床前明月光，疑是地上__ | 问题飞进黑箱 |
   | … | | | | | |

   起始时间 = （小节号 − 1）× 240 / BPM（上例为 88 BPM）。每集总时长 = 总小节数 × 240 / BPM，在讲解稿阶段就是确定的。

2. **作者生成说唱**：作者按同一 BPM、同一段落结构用 ACE 生成，再把人声对齐到小节网格上。
3. **动画阶段**：`scene.py` 直接按小节表计算时间点，字幕在小节线（必要时在拍点）上切换，关键动画的起落也卡在小节线上；`common/` 里新增一个“节拍模式”的字幕工具，替代 `self.say()` 的“按阅读时间自动补时”逻辑。字幕可比演唱提前约 0.1–0.2 秒出现，方便观众先看到字。
4. **合成**：画面 + 作者的说唱音轨，不再需要 `music.py` 生成的背景音乐。

这样画面和人声互不等待：只要双方都对齐同一张小节表，就能直接合在一起。

### 2.6 风格边界

- 参考 3Blue1Brown 的**视觉语言**（深色底、几何、颜色编码、变换动画），**不照搬**其具体画面和示例；手写数字网络是公共的经典教学例子，可以用，但构图、配色、镜头自己设计。
- 不用任何真实公司的 logo、真实游戏画面或真人照片；提到具体模型或系统（GPT-3、InstructGPT、DeepSeek-R1、AlphaGo、CLIP、SynthID 等）只作为论文和公开报道中的事实引用。

### 第 01 集　机器怎么“学”：一台会自己拧旋钮的函数

**核心问题**：人们说 AI 在“学习”，机器到底是怎么学的？

**一句话答案**：不写规则，给例子；AI 是一个带很多旋钮（参数）的函数，“学习”就是自动调旋钮，让它在例子上的误差越来越小，并且在没见过的新例子上也答得对。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 开场：「床前明月光，疑是地上__」丢进一个黑箱，黑箱吐出“霜”。黑箱里是什么？先倒回最简单的情况。传统编程：人写规则 → 机器执行。可是“这张图是不是猫”这种事，规则写不出来 |
| 主歌二 | 机器学习：给机器大量“题目 + 答案”，让它自己找规律。最简单的例子：气温 → 冷饮销量，散点图上画一条直线 y = w·x + b，只有 2 个旋钮：斜率 w、截距 b |
| 主歌三 | 怎么判断直线好不好：每个点到直线的竖直距离就是误差，把误差平方后取平均 = **损失**。学习 = 找让损失最小的那组旋钮。旋钮多了，函数就能弯成各种形状 |
| 桥段 | 顿悟句：**学习就是拧旋钮** |
| 主歌四 | 背答案 ≠ 学会：一条疯狂扭动、穿过每个点的曲线损失为 0，但遇到新数据就错得离谱（**过拟合**）。所以要留一部分数据当“考试”（训练集 / 测试集）。最后放一张三层同心圆：人工智能 ⊃ 机器学习 ⊃ 深度学习（“人工智能”一词出自 1956 年达特茅斯会议的提案，提案写于 1955 年） |
| 尾声 | 预告：旋钮成千上万的时候，这个函数长什么样？ |

**可视化创意**
- 片头：黑箱是一个半透明的立方体，问题从左边飞进去，“霜”从右边出来；箱体上贴一个旋钮面板，计数器显示 `? 个旋钮`。
- 散点图 + 直线，屏幕右侧两个实体旋钮（w、b），转旋钮时直线实时转动、平移；每个点到直线拉一根红色竖线（误差），红线的平方画成红色小正方形，所有小正方形的总面积就是损失，用一个红色进度条显示。
- 过拟合：同一组点，一条平滑直线和一条高次多项式曲线并排；新加入的测试点（空心圆）出现后，曲线的误差红线突然变得很长。
- 旋钮计数器第一次定格：`2`。

**衔接**：开启全系列，埋下“黑箱”“旋钮计数器”“床前明月光”三个锚点 → 第 2 集打开黑箱，看成千上万个旋钮的函数长什么样。

**说唱方向**
- **经典 boom bap，88 BPM**：鼓点干净、低频稳、采样感强，叙事性最好，第一集先让观众习惯“边听说唱边看讲解”。
- 主韵 **发花辙（a）**：答、法、它、差、下、话。
- 副歌示意：
  > 不写规则，只把例子喂给它
  > 让它自己去摸索方法
  > 猜错了，就量一量误差
  > 拧一拧旋钮，再来一下
  > ——一层一层，把黑箱打开

**准确性红线**
- “学习”说的是监督学习的最小模型，片中注明“最简单的一种”，不要说“所有 AI 都是这样学的”。
- 损失函数这里用均方误差，不要泛化成“所有损失都是平方”。
- 直线拟合其实可以用公式直接解出来；片中只说“可以一点点试着调”，不要说“只能靠试”。真正的“怎么调”留给第 3 集。

### 第 02 集　神经网络：一层一层的小开关

**核心问题**：要识别手写数字这种“写不出规则”的东西，黑箱里该装一个什么样的函数？

**一句话答案**：神经网络就是很多“神经元”分层连接；每个神经元只做一件简单的事：把输入**加权求和、加偏置，再过一个非线性开关**。简单的单元一层层叠起来，就能拼出极其复杂的函数。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 任务：手写数字识别（MNIST：28×28 像素灰度图，6 万张训练图、1 万张测试图）。28×28 = 784 个像素 → 784 个 0 到 1 之间的数，这就是输入 |
| 主歌二 | 一个神经元：每个输入乘一个权重（旋钮），加起来，再加一个偏置（也是旋钮），然后过激活函数。现代常用 ReLU：负数变 0，正数原样输出。“亮度”就是激活值 |
| 主歌三 | 分层：784 → 16 → 16 → 10。输出层 10 个神经元对应 0–9，哪个最亮就判成哪个数字。数一数旋钮：784×16+16 + 16×16+16 + 16×10+10 = **13,002** 个 |
| 桥段 | 为什么一定要“开关”（非线性）？没有它，多少层线性运算叠起来都等于一层，只能画直线。有了它，每一层都能把空间“折”一下 |
| 主歌四 | 叠得够多，就能逼近几乎任何形状（万能逼近定理的大白话：足够多的折线段可以拼出任意平滑曲线）。澄清：“神经元”只是**受大脑启发的比喻**，人工神经元比生物神经元简单得多。训练好以后，这个小网络在测试集上能达到约 96% 以上的准确率 |
| 尾声 | 预告：13,002 个旋钮一开始全是随机的，网络在瞎猜。该往哪边拧？ |

**可视化创意**
- 一个手写的“7”像素化成 28×28 网格，每个格子的灰度变成一个数，网格“抽丝”成一列 784 个圆点（输入层）。
- 单个神经元放大：输入连线的粗细 / 颜色表示权重（黄正、蓝负），求和后进入一个 ReLU 折线小图，输出点亮。
- 整个网络：激活值像灯一样逐层点亮，输出层“7”最亮。
- **折纸比喻**：二维平面上两团交错的点（例如两条交织的螺旋），线性分类器只能画一条直线分不开；每加一层 ReLU，平面被折叠、拉伸一次，最后两类点被分开。
- 万能逼近：一条平滑曲线，用 2 段、5 段、20 段 ReLU 折线去拼，越拼越像。
- 旋钮计数器：`2 → 13,002`（数字滚动）。

**衔接**：承接第 1 集的“带旋钮的函数”，给出它的具体形状 → 第 3 集解决“1.3 万个旋钮往哪边拧”。

**说唱方向**
- **synthwave 电子说唱，96 BPM**：复古合成器琶音 + 霓虹感音色，配合“灯一层层点亮”的电路画面。
- 主韵 **中东辙（eng/ing）**：灯、层、明、精、景、型。
- 副歌示意：
  > 每个神经元，像一盏灯
  > 加权求个和，够亮才点明
  > 一层传一层，越叠越精
  > 简单的开关，拼出整片风景
  > ——一层一层，把黑箱打开

**准确性红线**
- 不能说“神经网络模拟了人脑”。只能说“受到启发”。
- 3Blue1Brown 那类教程用 sigmoid，现代网络多用 ReLU 及其变体；我们用 ReLU，并可一句带过“早期用 S 形曲线”。
- “隐藏层的神经元在找笔画、圆圈”只是一种**希望**，实际训练出的隐藏层往往没那么好解释，片中要说清（这也为第 10 集“看不透的黑箱”埋线）。
- 万能逼近定理只保证“存在”这样的网络，不保证能训练出来，也不保证数据够用。

### 第 03 集　梯度下降：蒙着眼睛下山

**核心问题**：1.3 万个（未来是千亿个）旋钮，一开始全是随机的，怎么知道每个该往哪边拧、拧多少？

**一句话答案**：把损失想象成一片山地，位置 = 所有旋钮的取值，高度 = 损失。看不见整座山，但摸得到脚下哪边最陡（梯度）；往最陡的下坡方向迈一小步，反复走，损失就越来越低。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 回到第 1 集的直线：只有 w、b 两个旋钮时，可以把每组 (w, b) 的损失画成一张曲面，像一个碗。最好的直线就在碗底 |
| 主歌二 | 但真实网络有上万维，画不出来，也不可能每个组合都试一遍。办法：只看脚下。**梯度** = 每个旋钮各自往哪边拧会让损失上升最快，以及有多快；反过来走就是下降最快 |
| 主歌三 | **学习率** = 步子多大。太小：走到天荒地老；太大：在山谷两壁之间来回弹，甚至越弹越高。每一步：算梯度 → 每个旋钮减去“学习率 × 梯度” |
| 桥段 | 顿悟句：**看不清整座山，只要知道脚下哪边陡** |
| 主歌四 | 实际训练：每次只抽一小批数据估算梯度（**随机梯度下降**），步伐有点抖，但又快又够用。会不会困在小坑里？高维空间里真正的“四面都是上坡”的坑比想象中少，更常见的是马鞍形的平地；实践中常用带“惯性”的改进方法（如 Adam）。同时回扣第 1 集：要看的是测试集上的误差，不只是训练损失 |
| 尾声 | 预告：两个旋钮的梯度好算，几万个、几亿个呢？总不能一个一个地去试吧 |

**可视化创意**
- **双屏联动**：左边是第 1 集的散点图和直线，右边是 (w, b) 的损失曲面（3D 碗状，ThreeDScene）。一个小球在曲面上一步步下滑，左边直线同步转向数据。
- 俯视等高线图：每一步画一支绿色箭头（负梯度方向），箭头连成折线。
- 学习率对比：同一个起点，三个小球（小步、合适、大步），大步那个在峡谷里左右弹跳并飞出画面。
- “蒙眼下山”的抽象版：浓雾中的山地，只在小球脚下亮起一圈坡度。
- 小批量：完整数据的梯度箭头（白）和每一小批的梯度箭头（绿，带抖动）叠在一起，平均方向基本一致。
- 马鞍面：一个面在一个方向是谷、另一个方向是脊，小球在上面先变慢、再滑走。

**衔接**：承接第 2 集的“很多旋钮”和第 1 集的“损失” → 第 4 集解决“梯度到底怎么高效地算出来”。

**说唱方向**
- **lo-fi hip-hop，80 BPM**：全系列最慢的一集，配合“一步一步”“雾中下山”的氛围，也正好给 3D 画面留时间。
- 主韵 **由求辙（ou/iu）**：陡、走、留、够、头、透。
- 副歌示意：
  > 看不清整座山，先摸摸脚下哪边陡
  > 朝下坡迈一步，别贪大也别停留
  > 一步一步往低处走
  > 误差越来越小，直到足够
  > ——一层一层，把黑箱打开

**准确性红线**
- 梯度是“上升最快的方向”，我们走负梯度；歌词和画面箭头方向要一致。
- 不要说“梯度下降保证找到最优解”；对神经网络只能说“通常能找到足够好的解”。
- “高维空间局部极小值少、鞍点多”要说成研究上的观察和经验，不说成定理。
- 不要把 SGD 说成“随机乱走”：随机的是抽哪一批数据，方向仍然是那一批数据上的梯度。

### 第 04 集　反向传播：把错误一层层传回去

**核心问题**：网络答错了，13,002 个旋钮里谁的责任大、谁的责任小？怎样一次性算出所有旋钮的梯度？

**一句话答案**：从输出端的误差出发，借助“链式法则”把责任一层层往回分配：一次前向计算 + 一次反向计算，就能得到全部旋钮的梯度，计算量和前向计算是同一个量级。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 笨办法：每个旋钮单独拧一点点，看损失变多少。1.3 万个旋钮就要多算 1.3 万次；千亿个旋钮根本不可能 |
| 主歌二 | 从最后一层看：网络把“3”认成了“8”。想让“3”更亮，有三种办法：调这个神经元的偏置、调连向它的权重（尤其是那些来自很亮的上一层神经元的权重）、让上一层的神经元变亮或变暗。“上一层该怎么变”就是传回去的误差信号 |
| 主歌三 | **链式法则 = 齿轮组**：A 转一圈带 B 转 2 圈，B 转一圈带 C 转 3 圈，那 A 转一圈 C 转 6 圈。影响沿着链条相乘。反向传播就是从输出端开始，一层一层把这些“传动比”乘回去。每个权重的梯度 ≈ 它的输入有多亮 × 它下游的误差信号有多大 |
| 桥段 | 顿悟句：**错误从后往前流，每个旋钮都分到自己那一份** |
| 主歌四 | 训练循环一次完整走一遍：前向（猜）→ 算损失（对答案）→ 反向（分责任）→ 更新（拧旋钮）→ 下一批数据。历史：这种思想更早就有人提出，1986 年 Rumelhart、Hinton、Williams 在《自然》上的论文让它广为人知。现代深度学习框架都会自动完成这一步（自动求导） |
| 尾声 | 本季第一部分收尾：函数 + 损失 + 梯度下降 + 反向传播，这就是“学习”的全部机关。预告：可是，文字不是像素，机器怎么读一句话？ |

**可视化创意**
- 笨办法：13,002 个小旋钮排成矩阵，一个一个闪烁，旁边计时器飞速转，最后画面出现 “× 1750 亿？” 并崩成灰。
- 齿轮组：三个咬合的齿轮，标注传动比，转动时上方显示 2 × 3 = 6；然后齿轮链变形为网络中的一条连线路径。
- **反向流动**：前向时蓝色光脉冲从左往右流；答错后，红色误差脉冲从输出层往左回流，每经过一根连线，连线旁的黄色小旋钮按分到的“责任”大小转动，转的幅度不同。
- “谁亮谁背锅”：上一层亮的神经元连出的线，在反向时被标得更粗（梯度大），直观体现“梯度 ∝ 输入激活”。
- 训练循环的圆环图（前向 → 损失 → 反向 → 更新）转动若干圈，旁边准确率曲线上升、误判的数字逐渐变对。

**衔接**：承接第 3 集的“需要梯度” → 结束第一部分。下一个发布的是番外一（同样的训练方法用在看图上），之后第 5 集转向语言；本集尾声仍预告第 5 集，番外一作为“岔路”单独预告。

**说唱方向**
- **工业说唱（industrial hip-hop），95 BPM**：金属敲击、机械噪声做打击乐，像齿轮咬合；主歌四可以用一段“循环式”的重复 flow 对应训练循环。
- 主韵 **梭波辙（o/e/uo）**：错、说、拨、过、多、作。
- 副歌示意：
  > 答案错了，到底是谁的错
  > 从最后一层，往回追着说
  > 链式法则，一环一环往回拨
  > 每个旋钮那一份，一个都不漏过
  > ——一层一层，把黑箱打开

**准确性红线**
- 反向传播**只负责算梯度**，“更新旋钮”是梯度下降那一步；两者别混成一个概念。
- 反向传播不是 1986 年才发明的：反向模式自动微分（Linnainmaa，1970）和 Werbos（1974）更早，1986 年的论文让它在神经网络里流行开来。
- “反向一次的计算量和前向同一量级（约两倍）”可以说；不要说“完全免费”。
- 大脑是否用反向传播学习仍有争议，片中不做暗示。

### 第 05 集　词向量：把文字变成一串数字

**核心问题**：神经网络只会算数字，它怎么“读”文字？

**一句话答案**：先把文字切成一小块一小块的 **token**（中文常译“词元”；画面第一次出现时标注中文，之后歌词和画面都用 token），每个 token 对应一个很长的数字列表（**向量**），可以看成高维空间里的一个点。训练会让意思相近的词靠在一起，甚至让某些“方向”带上含义。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 「床前明月光」被切成 token：常见的字和词通常是一个 token，生僻的会被拆成更小的片段。每个 token 有一个编号，词表大小通常是几万到二十多万（GPT-2 是 50,257） |
| 主歌二 | 编号只是名字，没有“意思”。所以每个 token 都配一个向量：一长串数字（GPT-3 里每个是 12,288 个数）。这张“token → 向量”的大表本身也是旋钮，一开始是随机的，训练中被慢慢调好 |
| 主歌三 | 训练之后，意思相近的词在空间里离得近（猫和狗近，猫和冰箱远）。更神奇的是方向：在经典的词向量实验里，“国王 − 男人 + 女人”最接近“女王”；“巴黎 − 法国 + 意大利”接近“罗马” |
| 桥段 | 顿悟句：**意思变成了位置，关系变成了方向** |
| 主歌四 | 问题来了：「苹果」在“削个苹果”和“苹果手机”里是同一个向量，可意思完全不同。词向量只是起点，必须让每个词看到上下文才行。彩蛋：因为模型看到的是 token 不是字母，早期模型常数不对 “strawberry” 里有几个 r |
| 尾声 | 预告：怎样让每个词都“看一眼”周围的词，再更新自己的意思？ |

**可视化创意**
- 一句话被“刀光”切成彩色小方块（蓝色 token 块），每块下面浮出编号，再展开成一根长长的数字条（向量）。
- 高维空间用 3D 投影表示：token 点云旋转，动物、食物、城市各自成团。
- 向量算术：从“国王”出发，减去“男人→女人”的箭头的反方向……画面用平行四边形展示“国王—女王”与“男人—女人”两条近似平行的箭头。
- “苹果”的两个句子并排，同一个点被两股力量往“水果团”和“科技团”两个方向拉——为第 6 集埋悬念。
- strawberry：单词被切成几个 token 块，字母藏在块里看不见。
- 旋钮计数器：加上“词嵌入表”这一大块旋钮（GPT-3：50,257 × 12,288 ≈ 6.2 亿个，仅占 1750 亿的很小一部分）。

**衔接**：承接第 2–4 集（向量是网络能处理的输入，嵌入表也是可学习的旋钮）→ 第 6 集用注意力解决“同一个词，不同意思”。

**说唱方向**
- **jazz rap，90 BPM**：贝斯 walking bass + 钢琴 / 小号采样，轻快、文艺，配合“词语住在空间里”的点云画面。
- 主韵 **江阳辙（ang）**：量、旁、王、样、方、上。
- 副歌示意：
  > 每个 token 都变成一串数，叫向量
  > 意思相近的，就住在一旁
  > 国王减男人加女人，接近女王
  > 数字里装着词的模样
  > ——一层一层，把黑箱打开

**准确性红线**
- “国王 − 男人 + 女人 ≈ 女王”来自 word2vec 一类的静态词向量（Mikolov 等，2013），而且计算最近邻时通常排除了输入的那几个词；不要说成“大模型里精确成立”。用“接近”“经典实验”来表述。
- token 不等于字、也不等于词，不同模型的切法不同；中文切分不要给“一个汉字 = 一个 token”这种固定换算。
- 12,288 维是 GPT-3 的数，要标注出处，不说成“所有大模型”。
- strawberry 的例子要加时间限定：“早期模型常错”，现在的很多模型已经能答对。

### 第 06 集　注意力：每个词都在看别的词

**核心问题**：一个词的意思取决于上下文。模型怎么让每个词“看见”句子里和它相关的词？

**一句话答案**：每个 token 提出一个“问题”（Query），亮出一个“标签”（Key），准备一份“信息”（Value）。问题和标签越匹配，就从那个词那里拿越多信息，加到自己身上。于是“苹果”看到“手机”，就往科技那边挪。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 例句：「小明把苹果递给了妹妹，因为她饿了」。“她”是谁？人一眼看出是妹妹，模型需要一个让“她”去找“妹妹”的机制 |
| 主歌二 | **Q / K / V**：每个 token 的向量分别乘三组旋钮矩阵，得到三个新向量。Q = 我在找什么；K = 我能提供什么；V = 我要传过去的内容。用 Q 和每个 K 做点积（对得上就分高） |
| 主歌三 | 分数经过 softmax 变成加起来等于 1 的比例（**注意力权重**）；按比例把各个词的 V 加权求和，加到“她”的向量上，“她”就带上了“妹妹”的信息。像 GPT 这样生成文字的模型，每个词只能看自己和前面的词，看不到后面（掩码），因为生成的时候后面的词还不存在 |
| 桥段 | 顿悟句：**意思不是一个词自己的，是它看了谁** |
| 主歌四 | **多头注意力**：同一层里有很多个“头”并行，各自找不同的关系（有的头可能在追代词，有的在找修饰关系）。GPT-3 每层 96 个头、共 96 层。注意力机制本身早在 2014–2015 年就用于机器翻译；2017 年 Transformer 论文（《Attention Is All You Need》）的标题意思是“只用注意力就够了” |
| 尾声 | 预告：注意力是零件，把它组装起来，就是聊天机器人的心脏 |

**可视化创意**
- 句子横排成蓝色 token 块，“她”发出一道紫色探照灯（Q），其余 token 头顶亮出“标签牌”（K），匹配度用连线粗细和亮度表示，“妹妹”那根最粗。
- 注意力矩阵：行 = 谁在看，列 = 被看的谁，格子亮度 = 权重；右上三角整块变灰（因果掩码），说明“不许偷看未来”。
- softmax：一排高低不一的柱子（分数）被“压”成总和为 1 的比例条，大的更大、小的更小。
- 向量更新：“苹果”的点在嵌入空间里，被“手机”传来的 V 箭头推着从水果团漂向科技团。
- 多头：同一个句子上同时画出多组颜色不同的注意力连线，像多台探照灯同时扫过。
- 公式彩蛋卡（角落）：`Attention(Q,K,V) = softmax(QKᵀ/√d)·V`。

**衔接**：承接第 5 集“同一个向量、不同意思”的问题 → 第 7 集把注意力与其他部件组装成完整的 Transformer，并让它真正开口说话。

**说唱方向**
- **trap，140 BPM，按 70 BPM 的半拍感写词**：808 低音 + 细碎 hi-hat，配合“探照灯扫来扫去”的画面；主歌密度要严格控制，见 2.2。
- 主韵 **一七辙（i / ü / -i）**：系、息、意、此、你、句。
- 副歌示意：
  > 每个词都在找，谁跟自己有关系
  > 提个 Query，亮出 Key，交出 Value 的信息
  > 越对得上，就分去越多注意
  > 一句话的意思，全靠互相看彼此
  > ——一层一层，把黑箱打开

**准确性红线**
- Q/K/V 的“问题、标签、内容”只是比喻；它们是学出来的线性变换，片中注明。
- “某个头专门负责代词”只能说“研究中观察到有的头像在做这类事”，不能说每个头都有清楚的分工。
- 因果掩码只针对 GPT 这类“从左到右生成”的模型；原始 Transformer 的编码器部分、BERT 这类模型可以双向看。片中说“像 GPT 这样生成文字的模型”。
- 注意力不是 2017 年才发明的（Bahdanau 等 2014 年已用于翻译）；2017 年的贡献是**完全用注意力替代循环结构**。

### 第 07 集　Transformer：一次只猜下一个词

**核心问题**：把注意力组装起来之后，聊天机器人到底是怎么“说话”的？

**一句话答案**：Transformer 就是“注意力层（词和词交流）+ 前馈层（每个词自己消化）”这一对组合，叠几十到上百层。最后一层输出下一个 token 的概率，挑一个接上，再把整句话送回去猜下一个。所有回答都是这样**一个 token 一个 token**地长出来的。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 一个 Transformer 块 = 注意力 + 前馈网络（MLP，就是第 2 集那种神经网络）。注意力让信息在 token 之间流动，前馈网络让每个 token 独自做进一步的计算 |
| 主歌二 | **残差流**：每个 token 的向量像一条传送带，每层只往上面“加一点修改”，而不是整个替换。GPT-3 叠了 96 层，大部分参数在前馈层里（约三分之二）。有研究认为前馈层承担了很多“记事实”的工作 |
| 主歌三 | 最后：把最后一个 token 的向量和每个候选 token 比一比，打出分数 → softmax → 下一个 token 的概率分布。「床前明月光，疑是地上」后面，“霜”的概率遥遥领先 |
| 桥段 | 顿悟句：**它只会猜下一个词，可是一直猜下去，就成了一段话** |
| 主歌四 | **自回归生成**：挑出一个 token 接到末尾，再整体送进去猜下一个，直到输出“结束”。挑的时候不一定总选概率最高的：“温度”低更稳定，温度高更多样，所以同一个问题每次回答可能不一样。一次能看的长度叫**上下文窗口** |
| 尾声 | 预告：现在机器有了，可是这 1750 亿个旋钮最初全是随机的。它们是怎么被调好的？ |

**可视化创意**
- 组装动画：第 6 集的紫色注意力模块和第 2 集的神经网络模块拼成一个“块”，然后像积木塔一样向上复制叠成高塔（画面上显示层数）。
- 残差流：每个 token 一条水平发光的传送带，穿过所有层；每层在带子上“加”一支小箭头，向量方向一点点偏转。
- 输出：最后的向量投影到词表上，形成一排金色概率柱，“霜”最高，“上”“面”“雪”等较低；温度滑块左右拖动，柱子变尖或变平。
- 自回归：选中的“霜”飞回输入末尾，整个塔重新点亮一遍，下一个概率柱出现（例如句号 / 下一句的开头）。
- 旋钮计数器：`13,002 → 175,000,000,000`（数字滚动到千亿量级，并显示“GPT-3，2020”）。

**衔接**：把第 5、6 集的零件和第 2 集的神经网络组装起来，“床前明月光”第一次得到“霜”的概率 → 第 8 集讲这些旋钮是怎么训练出来的。

**说唱方向**
- **big beat 电子 funk，100 BPM**：厚重的 breakbeat + funk 贝斯 + 合成器，能量比前面几集高，“组装完成、机器启动”的感觉；“一个字接一个字”可以做成节奏上一字一顿的切分。
- 主韵 **灰堆辙（ei / ui）**：谁、堆、队、回、位、对。
- 副歌示意：
  > 它只做一件事：下一个词是谁
  > 注意力加前馈，Transformer 一层层地堆
  > 每个词都打分，概率排好队
  > 挑一个接上去，再来一回
  > ——一层一层，把黑箱打开

**准确性红线**
- 96 层、12,288 维、96 头、1750 亿参数都是 **GPT-3** 的公开数字；今天的很多前沿模型不公开结构和参数量，不能把 GPT-3 的数说成“现在的大模型”。
- “前馈层储存事实”是研究中的一种解释（如把前馈层看作键值记忆），不是定论，用“研究认为”。
- “温度”影响的是采样，不改变模型本身。
- 生成的单位是 token，不是“字”；歌词里可以说“一个词一个词”，画面上标 token。

### 第 08 集　预训练：读遍互联网

**核心问题**：没人告诉模型“正确答案”，它怎么学会语法、常识、翻译、写代码？

**一句话答案**：预训练的任务只有一个：在海量文本上**猜下一个 token**。文本自己就是答案，不需要人工标注。要把下一个词猜得足够准，模型不得不学会语法、事实和一定的推理套路。规模（参数、数据、算力）越大，猜得越准，而且这种提升相当有规律。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | **自监督**：随便一段文字，每个位置都是一道题：遮住后面，猜下一个 token。互联网网页、书籍、百科、代码……全是现成的“练习册” |
| 主歌二 | 规模感：Llama 3（2024）用了约 15 万亿个 token 训练。一个人每分钟读约 300 个 token、不吃不睡，也要读几万年（约 9.5 万年）。最大的模型要上万块 GPU 连续跑上数周到数月；GPT-3 的训练计算量约 3×10²³ 次浮点运算 |
| 主歌三 | **规模定律**：在很宽的范围内，模型越大、数据越多、算力越多，预测误差就沿着一条很规律的曲线下降（Kaplan 等，2020）。后来发现参数和数据要一起加，单纯加大模型不划算（Chinchilla，2022：大约每个参数配 20 个 token） |
| 桥段 | 顿悟句：**想把下一个词猜准，就得先懂这个世界的一部分** |
| 主歌四 | 预训练完的叫**基座模型**：它是“文档续写机”，不是助手。问它“法国的首都是哪里？”，它可能接着写出更多考试题，而不是回答你。它也会照单全收数据里的偏见和错误。所谓“能力涌现”是否真的突然出现，学界还有争论，和怎么测量有关 |
| 尾声 | 预告：读遍互联网的它还只会续写。怎样把它变成一个会好好回答问题的助手？ |

**可视化创意**
- 一段文字，上面滑过一个“遮挡块”，每遮一个位置就弹出一道选择题，连成一条无限长的练习题传送带。
- 数据规模：一本书 → 一个书架 → 一座图书馆 → 一座城市那么多图书馆（比例尺示意，标注“示意”）；旁边一个小人读书，计时器跳到“约 9.5 万年”。
- 规模定律：双对数坐标上，不同大小的模型的训练曲线排成一组，包络线是一条很直的斜线；横轴“算力”往右，纵轴“误差”往下。
- 基座模型 vs 助手：同一个问题，基座模型续写出“2. 德国的首都是哪里？3. ……”，画面打一个问号。
- 旋钮计数器在这里配一行小字：“旋钮的数量早就超过了 1000 亿，而每一个都是被‘猜下一个词’这个任务调出来的。”

**衔接**：承接第 7 集的模型结构和第 3–4 集的训练方法（预训练 = 在海量文本上做梯度下降 + 反向传播）→ 番外二先用下棋讲清“只有奖励、没有标准答案”的强化学习 → 第 9 集把基座模型变成助手。

**说唱方向**
- **管弦史诗说唱，86 BPM**：弦乐、铜管、合唱铺底，体现“读遍人类文字”的规模。
- 主韵 **姑苏辙（u）**：目、录、读、书、步、库。
- 副歌示意：
  > 不用老师出题，文字本身就是题目
  > 盖住下一个词，猜对猜错都有记录
  > 万亿个 token，一个人读几万年也读不完这些书
  > 规模越大，误差就越往下走一步
  > ——一层一层，把黑箱打开

**准确性红线**
- “读几万年”必须写明假设（每分钟约 300 个 token、不间断阅读、15 万亿 token），属于数量级估算。
- 3×10²³ FLOPs 是 GPT-3 的数（Brown 等，2020；也可由“6 × 参数量 × token 数”估算核对），不要说成“现在的模型”。
- 规模定律是经验规律，在一定范围内成立，不是物理定律；不要暗示“无限加大就无限变强”。
- “涌现”要呈现争议，不要说成确定结论。
- 基座模型“不回答问题”是倾向，不是绝对；它有时也会直接回答。

### 第 09 集　后训练：从续写机器到 AI 助手

**核心问题**：基座模型只会续写，为什么我们用到的聊天机器人会好好回答、拒绝有害请求、还会“想一想再答”？

**一句话答案**：在预训练之后再做“后训练”：先用示范对话教它一问一答的格式（监督微调），再用人或 AI 对回答的评价来强化好的回答（基于反馈的强化学习等），近年还会用能自动判对错的题目来训练它的推理。旋钮还是那些旋钮，只是被拧向了“好助手”的方向。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | **对话其实也是续写**：聊天被排成一种固定格式的文档（“用户：……助手：……”），模型续写的是“助手”那一段。所以变成助手不需要换模型，只需要让它擅长续写好助手的回答 |
| 主歌二 | **监督微调（SFT）**：人写一批高质量的“问题 + 理想回答”示范，在上面继续训练（还是猜下一个 token）。数据量比预训练小得多，但质量要求高 |
| 主歌三 | **基于人类反馈的强化学习（RLHF）**：给同一个问题生成两个回答，人来挑哪个更好 → 用这些比较训练一个“打分模型” → 让模型朝高分方向调整，同时不能离原来的模型太远。InstructGPT（2022）里，13 亿参数、经过这套训练的模型，回答比 1750 亿参数的 GPT-3 更受评审者喜欢。变体：用一份写明原则的“宪法”让 AI 来给反馈（Constitutional AI，2022）；直接从偏好对里学、跳过单独的打分模型（DPO，2023） |
| 桥段 | 顿悟句：**大小没变，方向变了** |
| 主歌四 | **推理训练**：数学题、编程题的答案能自动判对错，就用“答对给奖励”来强化学习；模型逐渐学会先写出很长的思考过程再作答（OpenAI o1，2024；DeepSeek-R1，2025）。风险：模型会学会“讨好打分者”，比如一味附和用户（谄媚），或者钻奖励的空子，这都是后训练要专门对付的问题 |
| 尾声 | 预告：现在它会聊天、会思考了。可它说的话都靠得住吗？ |

**可视化创意**
- “对话即文档”：一个聊天界面的气泡被“掀开”，露出底下其实是一整段带角色标记的文本，光标停在“助手：”后面。
- SFT：示范答案像描红字帖，模型的输出在上面一笔笔对齐。
- RLHF：两个回答卡片并排，一只手点选其中一个；大量的“左 > 右”比较汇成一个打分仪表；模型的输出分布在“分数山”上被推往高处，同时被一根弹簧（与原模型的距离约束）拉住，不让它跑太远。
- 旋钮面板：数字**不变**（1750 亿），但每个旋钮的指针轻轻偏转了一下——呼应“大小没变，方向变了”。
- 推理训练：一道数学题，模型生成多条解题路线，答对的路线亮绿、答错的变灰，亮绿的路线被“加粗”。
- 谄媚：用户说“我觉得 2+2=5”，一个没训练好的模型点头附和，画面打红叉。

**衔接**：承接第 8 集的基座模型和番外二的“奖励 → 调高概率”（人类反馈强化学习和推理训练就是把下棋的那一套搬到语言上；没看过番外二的观众，主歌三会用两三小节快速回顾）→ 第 10 集讨论它的能力边界与局限。

**说唱方向**
- **R&B 旋律说唱，90 BPM**：比前面更“温和”，配合“变成助手”的主题；桥段可以用副歌旋律放慢版。
- 主韵 **怀来辙（ai）**：AI、来、在、改、待、外。系列标签句「一层一层，把黑箱打开」本身也押 ai，这一集副歌可以和标签句无缝衔接。
- 副歌示意：
  > 读完了互联网，它还不懂怎么当个 AI
  > 先看示范答案，学着一问一答地来
  > 两个回答摆一起，人来挑哪个更实在
  > 好的多给分，就这样一点点地改
  > ——一层一层，把黑箱打开

**准确性红线**
- InstructGPT 的结论要原样表述：**评审者更喜欢** 13 亿参数 InstructGPT 的输出，而不是“它全面比 GPT-3 聪明”。
- RLHF 里人类给的通常是**比较 / 排序**，不是打绝对分；奖励模型是另外训练出来的一个网络。
- 各公司的具体后训练流程大多不公开，片中讲的是公开论文中的代表性方法，要注明。
- 推理模型的“思考过程”是生成出来的文本，不等于模型内部真实计算的完整记录（为第 10 集“看不透”埋线）。
- 不点名评价任何公司或产品的好坏。

### 第 10 集　能与不能：幻觉、工具与看不透的黑箱

**核心问题**：理解了原理之后，我们该怎么看待 AI：它为什么会一本正经地说错话？它是怎么查资料、用工具的？我们真的懂它吗？

**一句话答案**：它是一台极其强大的“下一个 token 预测器”，经过后训练成为助手：会编出看似合理的错话（幻觉），知识停在训练截止的那一天，对话里的“记忆”只是上下文；可以通过输出特殊指令来调用搜索、计算器、代码等工具；而它内部千亿个旋钮究竟在算什么，人类才刚刚开始看懂。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | **幻觉**：模型学的是“什么样的话看起来像对的”，所以没把握时也可能生成流利但错误的内容，比如编造不存在的论文。原因之一：训练和评测常常奖励“猜一个答案”而不是“说不知道”。缓解办法：训练它说不确定、让它查资料、让人核对 |
| 主歌二 | **知识截止与记忆**：旋钮在训练结束后就固定了，聊天时并不会因为你说的话而改变；它“记得”刚才的话，是因为整段对话每次都作为上下文重新输入。上下文窗口有长度上限 |
| 主歌三 | **工具与智能体**：模型可以输出一段约定格式的“调用指令”（比如“搜索：……”），程序去执行，把结果贴回上下文，模型再接着写。查网页、算数、跑代码都是这样完成的；多轮循环下去，就是“智能体” |
| 桥段 | 顿悟句：**我们造出了它，却还没完全看懂它** |
| 主歌四 | **可解释性**：研究者发现，模型内部的很多概念不是由单个神经元表示，而是由许多神经元的组合方向表示（叠加）；用“稀疏自编码器”之类的工具能找出成千上万个可理解的特征，比如一个对应“金门大桥”的特征，放大它，模型就会三句话不离金门大桥（Anthropic，2024）。这关系到安全：要确认 AI 按我们希望的方式工作，就得能看懂它在想什么 |
| 尾声 · 正片回顾 | 追踪「疑是地上__」的“霜”的一生：切成 token → 查表变成向量 → 注意力让 token 互相看 → 前馈层消化 → 几十层叠加 → 概率分布 → 采样出“霜”。而这一切旋钮是怎么来的：损失 → 梯度下降 → 反向传播 → 预训练 → 后训练。最后一句：**不是魔法，是可以被理解的数学**——一层一层，把黑箱打开 |

**可视化创意**
- 幻觉：模型生成一条格式完美的“参考文献”，一个放大镜扫过，作者、期刊都对不上，卡片碎成像素。
- 记忆：每一轮对话，整个聊天记录被重新“喂”进模型（画面上历史消息整体飞回输入端），旋钮面板始终不动。
- 工具调用：模型输出中出现一张“工具卡”，卡片飞出画面到计算器 / 搜索框，结果卡飞回来插进上下文，模型继续生成。
- 可解释性：残差流里的一个向量被拆成许多稀疏的“特征方向”，其中一个亮起并贴上标签；把它“调大”，输出文字开始不停提到这个主题。
- **正片回顾长镜头**：从第 1 集的黑箱开始，镜头穿过箱壁，依次经过前 9 集的标志性画面（散点直线 → 网络灯阵 → 下山小球 → 红色反向流 → 词向量点云 → 注意力探照灯 → Transformer 高塔 → 图书馆 → 旋钮偏转），最后从输出端出来，“霜”字落下。旋钮计数器从 2 一路滚到千亿，再定格。

**衔接**：收束正片，回到第 1 集的黑箱。片尾加一张“番外预告”卡：同样的旋钮和下山，还能看图、听声、画画——引出番外三到五。

**说唱方向**
- **钢琴 conscious rap，84 BPM**：钢琴主导、偏沉思，适合讲局限和反思；尾声如果 ACE 可控，可以引用第 1 集的伴奏动机作为呼应。
- 主韵 **言前辙（an / ian）**：编、见、延、面、线、限。
- 副歌示意：
  > 说得再流利，也可能是一本正经地乱编
  > 知识停在训练那天，后来的事它没看见
  > 给它搜索和计算器，能力就往外延
  > 我们造出了它，却还没完全看清里面
  > ——一层一层，把黑箱打开
- 尾声建议写成**一集一小节的回顾句**（10 小节对应 10 集），每句一个关键词，节奏可以加快（这是正片唯一允许快嘴的地方，因为内容都是已讲过的知识）。

**准确性红线**
- 幻觉不是“故意撒谎”，歌词不用“谎言”一类带意图的词。
- “评测奖励猜测导致幻觉”是近年研究提出的一种解释（OpenAI，2025），只说“原因之一”。
- 不渲染“AI 有意识 / 没意识”的结论；不做“AI 很快会取代人类”之类的预测。
- 金门大桥例子要准确：来自 Anthropic 2024 年的《Scaling Monosemanticity》及其演示，是通过放大一个特征实现的。
- 记忆说法要严谨：有的产品会把过往对话摘要存起来再塞回上下文，这也属于“上下文”，不是旋钮在变。

### 番外一　卷积网络：AI 怎么看图

**发布位置**：正片第 04 集之后（发布序 5）

**核心问题**：第 2 集把图片拉成一长串像素喂给网络。可一只猫往左挪几个像素，所有输入数字都变了；照片一大，旋钮数也会爆炸。AI 到底怎么“看”图？

**一句话答案**：卷积网络用一个很小的“滑动窗口”（卷积核）在整张图上一格格扫过，到处找同一种局部图案（竖边、横边、角、纹理）。同一个卷积核在每个位置共用同一套旋钮，所以旋钮少、图案挪了位置也能找到。一层层叠加，就从线条拼成形状，从形状拼成物体。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 回扣第 2 集：784 个像素拉成一列，丢掉了“谁挨着谁”的信息。猫在图片左边还是右边都是猫。照片一大问题更严重：一张 1000×1000 的彩色照片有 300 万个数，第一层如果每个神经元都连到所有像素，单个神经元就要 300 万个权重 |
| 主歌二 | **卷积核**：一个 3×3 的小方格，9 个权重（旋钮）。把它盖在图上某个位置，对应格子相乘再相加（还是第 2 集的“加权求和”），得到一个数；滑到下一个位置再算一次，扫完全图得到一张新的图（**特征图**）。一个“左暗右亮”的卷积核，在竖边的地方输出最大，竖边检测器就有了 |
| 主歌三 | **权重共享**：同一个卷积核扫遍全图，只有 9 个旋钮（加一个偏置），图案挪到哪里，特征图上的亮点就跟到哪里。一层有几十到几百个卷积核，各找一种图案。再用**池化**或跨步把图缩小，后面的层“看到”的范围（感受野）越来越大：第一层找边，往后是角和纹理，再往后是眼睛、轮子这样的部件，最后是整个物体（研究者把各层特征可视化后观察到这种层次） |
| 桥段 | 顿悟句：**同一副眼光，扫遍整张图** |
| 主歌四 | 卷积核不是人设计的，是梯度下降和反向传播学出来的（回扣第 3–4 集）。历史：LeCun 等人在 1989 年就用卷积网络识别手写邮编；2012 年 AlexNet 在 ImageNet 比赛（约 120 万张训练图、1000 类）上把前五错误率降到 15.3%，第二名是 26.2%，开启了深度学习热潮。局限：加上人眼几乎看不出的微小扰动，就能让网络把熊猫认成长臂猿（对抗样本）。新趋势：Vision Transformer 把图片切成小方块当成 token，交给 Transformer 处理（第 5–7 集和番外三会讲到） |
| 尾声 | 回到正片：图片可以切成小块，文字呢？预告第 5 集 |

**可视化创意**
- 一张几何风格的简笔画（猫的轮廓或数字“7”）像素化，一个发光的 3×3 黄色窗口在上面一格格滑动；每停一处，九个格子的数字和卷积核数字逐对相乘，飞到右边累加成特征图上的一个像素。
- 竖边检测：原图里只有竖直边缘的位置在特征图上亮起；换一个“上暗下亮”的核，亮起的变成横边。
- 平移：图里的猫向右挪，特征图上的亮斑同步右挪（直观展示“图案挪到哪，特征跟到哪”）。
- 旋钮对比：左边“全连接”——一根根连线密密麻麻连满整张图，计数器飙到 300 万；右边“卷积”——只有一个 3×3 小窗，计数器显示 10。
- 特征金字塔：一叠叠越来越小、越来越多的特征图，旁边示意“边 → 角/纹理 → 部件 → 物体”，用自己画的抽象图案表示，不复制论文插图。
- ImageNet 柱状图：标出 2012 年 AlexNet 15.3% 与第二名 26.2% 的落差。
- 对抗样本：简笔熊猫 + 一层几乎看不见的彩色噪点 = 网络判为“长臂猿”（用示意图，不复刻原论文图片）。

**衔接**：依赖第 2 集（神经元、加权求和）和第 3–4 集（训练方法）→ 为第 5 集“切成小块变 token”铺垫，也为番外三（ViT）、番外四（扩散模型里的 U-Net 由卷积组成）打底。

**说唱方向**
- **80 年代 electro（808 鼓机 + 机械人声采样），100 BPM**：机器视觉的“扫描感”，鼓点规整，像扫描仪一格格前进。
- 主韵 **言前辙（an / ian）**：看、边、线、面、眼、脸。
- 英文词：ImageNet、AlexNet、Vision Transformer 唱英文。
- 副歌示意：
  > 一个小窗口，在图上一格一格地看
  > 找竖线找横线，找每一条边
  > 同一副眼光，扫过整张画面
  > 一层叠一层，从线条拼出一张脸
  > ——一层一层，把黑箱打开

**准确性红线**
- 卷积带来的是“**平移等变**”（图案挪了，特征图跟着挪），加上池化后才有一定程度的平移不变；不能说“完全不受位置影响”。
- 深度学习里的“卷积”严格说是互相关（不翻转卷积核），片中不展开，但不要在彩蛋卡上写错公式。
- “边 → 部件 → 物体”的层次是可视化研究中的观察，不是每个通道都能这样清楚地解释。
- AlexNet 不是第一个卷积网络（LeNet 更早）；15.3% 是前五错误率（top-5），要标明。
- 对抗样本是真实存在的问题，但不夸大成“AI 看图完全不可靠”。

### 番外二　强化学习：AI 怎么自己学会下棋

**发布位置**：正片第 08 集之后、第 09 集之前（发布序 10）

**核心问题**：下棋没有“每一步的标准答案”可抄，一步好棋往往几十步之后才见分晓。只知道最后的输赢，AI 怎么学？

**一句话答案**：这叫**强化学习**：AI 在环境里一步步行动，结果出来时得到奖励（赢 +1、输 −1），然后把“导致赢的那些动作”的概率调高一点、导致输的调低一点。经过海量试错，策略越来越强。AlphaGo 先学人类棋谱、再自我对弈；AlphaGo Zero 完全不看人类棋谱，从随机乱下开始自我对弈。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 和前面不一样：第 1–8 集都有“标准答案”（标签或下一个 token），下棋只有终局输赢。基本框架：**智能体**（下棋的 AI）、**环境**（棋盘和对手）、**状态**（当前局面）、**动作**（落子）、**奖励**（输赢） |
| 主歌二 | **策略网络**：一个神经网络，输入局面，输出每个落点的概率（回扣第 7 集“输出概率再采样”）。**策略梯度**的大白话：一局赢了，把这局里走过的每一步的概率都调高一点；输了就调低一点。单局很嘈杂（赢棋里也有臭棋），所以需要成千上万局来平均。这是第 4 集“责任分配”的时间版：几十步之后才知道输赢，哪一步的功劳最大？**价值网络**：再训练一个网络估计“这个局面我赢的概率”，不必等到终局就有信号 |
| 主歌三 | **AlphaGo**（DeepMind）：围棋合法局面约 2×10¹⁷⁰ 种，远超可观测宇宙的原子数（约 10⁸⁰），不可能穷举。做法：先模仿人类高手棋谱（约 3000 万个局面，监督学习）→ 再自我对弈强化 → 落子前用**蒙特卡洛树搜索**往前推演，由策略网络挑候选、价值网络判形势。2016 年 3 月以 4:1 战胜李世石；第二局第 37 手被评论员一度认为是失误，事后被视为妙手。2017 年 **AlphaGo Zero** 不用任何人类棋谱，从随机开始自我对弈，约 3 天就以 100:0 战胜了击败李世石的版本；之后的 **AlphaZero** 用同一套方法学会了国际象棋和将棋 |
| 桥段 | 顿悟句：**没人教它怎么下，只告诉它输赢** |
| 主歌四 | 局限：**奖励设计很难**。一个赛艇游戏里，AI 发现原地绕圈反复撞得分道具比跑完全程得分更高，就一直绕圈（奖励钻空子）。强化学习还需要海量试错，真实世界里很难这样试，所以多在模拟器和游戏里先行。连接第 9 集：人类反馈强化学习（RLHF）和推理训练，就是把这套“拿到奖励就调高概率”用在语言模型上——奖励来自人的偏好，或者来自题目答对与否 |
| 尾声 | 预告第 9 集：如果“赢”的定义变成“回答让人满意”，会发生什么？ |

**可视化创意**
- 19×19 极简棋盘（深底细线），黑白子用纯几何圆。智能体—环境循环图：箭头依次标“状态 → 动作 → 奖励”。
- 策略网络输出：棋盘上叠一层金色热力图，越亮越可能落子；采样出一个点，棋子落下。
- 策略梯度：一局结束显示“胜”，一道金光从终局沿着整局棋的每一手倒流回去，每一手对应位置的热力图都亮一点；另一局“负”，红光倒流，热力图暗一点。
- 价值网络：棋盘旁一根竖条显示“胜率”，随着每手棋上下波动。
- 树搜索：从当前局面长出一棵分叉树，策略网络只展开几个高概率分支，叶子上标价值网络给出的胜率。
- 第 37 手：在第五线上落下一子（“肩冲”），旁边一个人类评论员的简笔头像冒出问号，随后问号变成感叹号（不使用真实人物肖像）。
- 自我对弈：两个一模一样的网络面对面下棋，背景里等级分曲线一路上升，越过“人类顶尖”虚线。
- 奖励钻空子：一只几何小船在赛道角落不停绕圈，分数狂涨，终点线孤零零地闪着（不使用真实游戏画面）。
- 旋钮计数器：网络还是那套旋钮，标注“训练信号从‘标准答案’变成了‘奖励’”。

**衔接**：依赖第 2–4 集（网络与训练）和第 7 集（输出概率再采样）→ 直接为第 9 集的人类反馈强化学习和推理训练铺路。

**说唱方向**
- **国风说唱，88 BPM**：古筝 / 琵琶 / 笛子采样 + 808 低音，围棋本身就是中国的棋，最贴题；桥段可以只留古琴和人声。
- 主韵 **人辰辙（en / in / un）**：分、问、顿、阵、人、神。
- 英文词：AlphaGo、AlphaGo Zero 唱英文。
- 副歌示意：
  > 没人教它怎么下，只告诉它输赢的分
  > 赢了记住这一路，输了换个走法再问
  > 自己跟自己下，上百万盘不停顿
  > 第三十七手，连高手都看不懂这一阵
  > ——一层一层，把黑箱打开

**准确性红线**
- **AlphaGo 不是“完全自学”**：它先学了人类棋谱，再自我对弈，并结合树搜索；“完全不看人类棋谱”的是 AlphaGo Zero。歌词和画面必须分清这两个版本。
- AlphaGo Zero 的训练方式是“用树搜索的结果当老师来改进策略”，和上面“赢了就调高”的策略梯度不完全一样；片中把策略梯度作为强化学习的入门思想讲，讲 Zero 时不说它用的是同一个公式。
- 2×10¹⁷⁰ 是**合法局面数**，不是“对局数”。
- “第 37 手被认为是失误”说的是部分评论员的第一反应，不要说成“所有人类都看不懂”。

### 番外三　多模态：AI 怎么同时看图、听声、读字

**发布位置**：正片第 10 集之后（发布序 13）

**核心问题**：现在的 AI 助手能看照片、听语音。可第 5–7 集讲的 Transformer 只认 token，图片和声音是怎么进去的？

**一句话答案**：把一切都变成 token。图片切成小方块、声音切成小段，各自编码成和文字 token 一样长的向量，排进同一条队伍交给 Transformer。再用大量“图片 + 描述”配对训练，让同一个意思的图和文字在向量空间里靠在一起。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 回顾：Transformer 的输入就是一串向量（第 5 集）。它并不关心向量是从哪里来的，只要别的东西也能变成同样长度的向量，就能排进同一条队伍 |
| 主歌二 | **图片变 token**：Vision Transformer（ViT，2020）把图片切成 16×16 像素的小方块，每块拉平后乘一个矩阵（还是旋钮）变成一个向量，再加上“我在第几块”的位置信息。一张 224×224 的图 = 14×14 = 196 个图块 token。也可以先用番外一的卷积网络提取特征再送进来 |
| 主歌三 | **图文对齐**：CLIP（2021）用约 4 亿对网上的“图片 + 文字说明”，同时训练一个图像编码器和一个文本编码器：配对的图和文字向量拉近，不配对的推远（**对比学习**）。训练好以后，不用专门训练就能按文字给图片分类：比较这张图离“一张狗的照片”和“一张猫的照片”哪个更近。**看图的聊天助手**：把图像编码器的输出经过一个小小的“翻译层”接到语言模型的输入端（如 LLaVA，2023），再用图文对话数据训练 |
| 桥段 | 顿悟句：**图片、声音、文字，最后都说同一种语言——向量** |
| 主歌四 | **声音变 token**：声波 → 频谱图（横轴时间、纵轴频率，亮度是强度）→ 切成一段段变成向量。Whisper（2022）用约 68 万小时的多语言音频训练语音识别。反过来，图片和声音也可以作为输出生成（番外四讲画画）。局限：看图也会产生幻觉（说出图里没有的东西），数数、精确的空间位置关系仍然常出错 |
| 尾声 | 预告番外四：既然能把图片变成向量去理解，能不能反过来，从文字生成一张图？ |

**可视化创意**
- 一张几何风格的插画（山、月、房子，自己绘制）被网格切成 14×14 个小方块，方块逐个翻转、拉平成向量，飞进蓝色 token 队伍；队伍前面是图块 token，后面跟着文字 token“图里有什么？”。
- 两个圆盘形的向量空间（图片空间、文字空间）合并成一个，图片点和它的描述文字点之间连一根弹簧，配对的被拉近、不配对的被一股斥力推开。
- 相似度矩阵：行是图片、列是文字，训练中对角线越来越亮、其余格子越来越暗。
- 零样本分类：一张简笔狗图，三条候选文字“一张狗的照片 / 猫的照片 / 汽车的照片”，三根相似度柱，狗那根最高。
- 声音：一段波形展开成彩色频谱图，纵向切片一条条变成向量，加入同一条队伍。
- 视觉幻觉：模型描述图片时多说了一只“猫”，画面上那个位置是空的，打一个问号。
- 旋钮计数器：多了“图像编码器”“翻译层”两块旋钮。

**衔接**：依赖第 5–7 集（token、注意力、Transformer）、第 9 集（对话数据的训练）和番外一（卷积 / 看图）→ 番外四要用到的“文本编码器把提示词变成向量”在这里先讲清。

**说唱方向**
- **afrobeats 律动说唱，102 BPM**：跨文化的打击乐和摇摆律动，呼应“不同感官融到一起”；人声可以在副歌里加一点和声。
- 主韵 **中东辙（eng / ing / ong）**：中、通、懂、逢、声、听。
- 英文词：token、ViT、CLIP、Whisper、Transformer 唱英文。
- 副歌示意：
  > 图和声音，排进同一队伍中
  > 看的听的读的，从此全相通
  > 图文配对就拉近，彼此才能懂
  > 能读能看又能听，token 来相逢
  > ——一层一层，把黑箱打开

**准确性红线**
- 不说“多模态模型像人一样理解图片”。
- ViT 切块、CLIP 对齐、LLaVA 接翻译层都是**公开论文里的代表性做法**；商用多模态模型的具体结构多数没有公开，不能说“某产品就是这样做的”。
- 4 亿对是 CLIP 的数，68 万小时是 Whisper 的数，要标注出处。
- 声音也有不经过频谱图、直接从波形编码的方法，片中用“常见做法之一”。
- 插图全部自己绘制，不使用真人照片。

### 番外四　扩散模型：从噪声里画出一幅画

**发布位置**：番外三之后（发布序 14）

**核心问题**：AI 画画用的也是“猜下一个 token”吗？

**一句话答案**：目前很多主流的图像生成模型用的是**扩散模型**：训练时把清晰的图片一步步加噪声，直到变成一片雪花点，让网络学会“看一眼带噪声的图，猜出里面的噪声”；生成时从纯噪声出发，一步步去掉猜出来的噪声，文字提示在每一步给它指方向。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 回扣：这还是“带旋钮的函数 + 损失 + 梯度下降”，只是任务换了。从“理解图片”（番外一、三）换成“生成图片” |
| 主歌二 | **加噪（前向过程）**：一张图加一点点随机噪声，再加一点……经过上千步（DDPM 用 1000 步）变成纯雪花。这个过程是固定的公式，**不需要学** |
| 主歌三 | **去噪（反向过程）**：训练一个网络，输入“带噪图 + 现在是第几步”，输出“它猜的噪声”；损失就是猜的噪声和真实加进去的噪声之间的差（Ho 等，2020）。这个网络常用 **U-Net**：先用卷积一层层缩小看全局，再一层层放大还原细节（回扣番外一） |
| 桥段 | 顿悟句：**画画，就是一层一层擦掉噪声** |
| 主歌四 | **生成**：从一片随机雪花开始反复去噪，起点不同，画出来的就不同。**文字引导**：提示词先经过文本编码器（如番外三的 CLIP 文本编码器）变成向量，在去噪网络里通过注意力影响每一步；再用“有提示和无提示两次预测之差”放大提示的作用（无分类器引导）。**省算力**：Stable Diffusion 一类模型（2022）先把 512×512 的图压缩成 64×64×4 的“潜空间”，数字少了约 48 倍，在那里去噪，最后再解码回图片。改进的采样方法把上千步压缩到几十步 |
| 尾声 | 预告番外五：AI 画的图、写的字越来越像真的，怎么认出它们？ |

**可视化创意**
- 一张自己绘制的几何画（月亮和山）逐帧加噪，变成雪花；再倒放，雪花里逐渐浮现图像——但从另一片随机雪花倒放出来的是一张构图不同的月夜图。
- 噪声预测：带噪图 − “网络猜出的噪声” = 更清楚的一张，三张图用减号和等号排成算式。
- U-Net：一个 U 形的网络图，左边一路缩小（卷积 + 下采样），右边一路放大，中间有“跳线”把细节直接送到右边。
- 文字引导：同一片初始噪声，在一个二维示意空间里沿两条不同轨迹去噪，提示词“月亮”和“太阳”各走一条，终点分别是夜景和日景。
- 潜空间：512×512 的大方块被压成一个小方块，旁边显示“约 1/48”，去噪在小方块里进行，最后再放大回去。
- 旋钮计数器：网络换了，计数器依旧在。

**衔接**：依赖第 1–4 集（训练）、第 6 集（注意力，用于文字引导）、番外一（卷积 / U-Net）、番外三（文本编码器）→ 番外五讨论“怎么识别 AI 生成的内容”。

**说唱方向**
- **cloud rap，96 BPM**：梦幻、空灵的合成器铺底，人声加少量混响，配合“雪花中浮现画面”。
- 主韵 **遥条辙（ao / iao）**：噪、掉、找、道、描、调。
- 英文词：U-Net、Stable Diffusion、prompt 唱英文。
- 副歌示意：
  > 先把一张图，一点点加上噪
  > 再训练网络，学会把噪声一点点擦掉
  > 从一片雪花里，一步步把画面找
  > prompt 做指引，画什么它知道
  > ——一层一层，把黑箱打开

**准确性红线**
- 不说“所有 AI 画图都是扩散模型”（也有自回归、流匹配等方法），用“目前很多主流模型”。
- 前向加噪不需要学习；需要学的是去噪网络。
- 网络预测的是噪声（DDPM 的常见做法），也有预测原图或“速度”的变体，片中不说成唯一方式。
- 64×64×4、约 48 倍是 Stable Diffusion v1 在 512×512 分辨率下的数字，要标注。
- 不涉及任何真实艺术家或作品的风格模仿示例；训练数据版权争议不在本集展开，也不下结论。

### 番外五　文本水印：怎么认出 AI 写的字

**发布位置**：番外四之后，全系列最后一集（发布序 15）

**核心问题**：一段文字是人写的还是 AI 写的，认得出来吗？

**一句话答案**：光凭“文风像不像 AI”去判断很不可靠。更靠谱的办法是生成的时候就埋下**统计水印**：每写一个 token，都用一把密钥把词表随机分成“绿名单”和“红名单”，轻轻偏向绿名单。人读不出区别，但拿着密钥的人数一数绿色 token 的比例，就能用统计检验判断。不过改写会冲淡水印，而且没加水印的模型写的字，水印检测管不着。

**知识点**

| 段落 | 内容 |
|---|---|
| 主歌一 | 现状：靠“猜文风”的 AI 检测器误判很多。OpenAI 在 2023 年 1 月推出的 AI 文本分类器，只能识别出约 26% 的 AI 文本，同时把约 9% 的人类文本误判为 AI，半年后因准确率太低下线。研究还发现，一些检测器容易把非英语母语者写的英文误判为 AI 写的。所以思路换成：生成的一方主动做标记 |
| 主歌二 | 回扣第 7 集：模型每一步给出下一个 token 的概率，然后采样。水印就藏在采样这一步。**绿 / 红名单**（Kirchenbauer 等，2023）：用前一个 token 加上一把密钥算出一个随机种子，把整个词表随机分成两半，绿的一半分数加一点点，再照常采样。意思通顺的候选词里，绿词被选中的机会稍大 |
| 主歌三 | **检测**不需要模型，只需要密钥：重算每个位置的绿名单，数一数有多少 token 是绿的。普通文本大约一半是绿的（纯属运气）；带水印的文本明显偏多。例：200 个 token 里有 150 个绿词，期望是 100 个，偏离了约 7 个标准差（z ≈ 7），纯属巧合的概率不到万亿分之一。**低熵难题**：「床前明月光，疑是地上__」的下一个字几乎只能是“霜”，概率接近 1，加一点分也改变不了选择，这种地方藏不进水印；代码、标准答案也一样 |
| 桥段 | 顿悟句：**人读不出来，统计算得出来** |
| 主歌四 | **实际部署**：Google DeepMind 的 SynthID-Text 已用在 Gemini 上（《自然》，2024），在约 2000 万次真实回答的测试中，用户对质量的评价没有明显差别；它的具体算法和绿 / 红名单不同，但思路一样：在采样时埋入可检测的统计信号。**局限**：改写、翻译、人工修改会冲淡水印（文本足够长时往往仍能检测出一部分）；短文本难判断；需要生成方愿意加，开源模型可以不加；检测结果是概率证据，不能单凭它给人“定罪”。图片也有类似的水印和“内容凭证”技术 |
| 尾声 · 系列收尾 | 从第 1 集的黑箱到最后的水印：理解了它怎么工作，才知道该怎么用它、怎么判断它。最后一次落在系列标签句上 |

**可视化创意**
- 开场：两段并排的文字，一段人写、一段 AI 写，一个“检测器”指针在两者之间摇摆不定，最后指错。
- 词表网格：一把钥匙图标 + 前一个 token 一起投进一个“洗牌机”，词表格子随机变成一半绿一半红。
- 采样：一排金色概率柱，绿色候选的柱子被往上推了一小截，然后采样；被选中的 token 落进句子。
- 检测视角：同一段文字按绿 / 红上色。普通文本红绿参半，像随机噪点；水印文本绿色明显占多数。
- 统计检验：一条钟形曲线（运气的范围），普通文本落在中间，水印文本落在 z ≈ 7 的极右端，远到要把镜头拉远才看得见。
- 低熵：「疑是地上__」处，“霜”的概率柱几乎顶满，绿色加分的小箭头推不动它。
- 改写：水印文本里的一部分 token 被替换成灰色，绿色比例回落，钟形曲线上的点往中间滑。
- 片尾：全系列的旋钮计数器、黑箱、标签句最后一次出现，黑箱完全打开。

**衔接**：依赖第 7 集（概率与采样、温度）和第 10 集（幻觉与可信度）；番外四的“AI 生成图片”引出“如何识别生成内容”。作为全系列最后发布的一集，尾声收束全系列。

**说唱方向**
- **UK drill，142 BPM，按 71 BPM 的半拍感写词**：阴冷的滑音 808 和切分 hi-hat，营造“侦探破案”的氛围。
- 主韵 **乜斜辙（ie / üe）**：解、些、别、截、写、谢。
- 英文词：AI、token、SynthID 唱英文。
- 副歌示意：
  > 这段话是谁写？光看文风很难解
  > 生成时埋一把钥匙，绿词悄悄多一些
  > 人读不出来，拿钥匙一数就能鉴别
  > 可改写、翻译，会把印记冲淡一截
  > ——一层一层，把黑箱打开
- 尾声作为系列收尾，可以把 15 集的标题关键词各压成半句，快速回顾一遍。

**准确性红线**
- 水印只能证明“这段文字出自加了这种水印的模型”；**检测不到水印不等于是人写的**。
- 绿 / 红名单是 Kirchenbauer 等人提出的一类方法，不同系统做法不同；SynthID-Text 的细节以论文为准，不说成“同一个算法”。
- OpenAI 分类器的数字（26%、9%）和下线时间（2023 年 7 月）要原样引用。
- “纯属巧合的概率不到万亿分之一”要写明计算条件（绿名单占一半、200 个 token、150 个绿词）。
- 只讲“改写会削弱水印”这个结论，不演示具体的去水印方法。
- 不点名指责任何个人或机构用 AI 写作；强调检测结果不能单独作为处罚依据。
