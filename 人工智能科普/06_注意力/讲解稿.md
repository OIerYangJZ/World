## 大纲

**核心问题**：一个词的意思取决于上下文。模型怎么让每个词“看见”句子里和它相关的词？

**一句话答案**：每个 token 提出一个“问题”（Query），亮出一个“标签”（Key），准备一份“信息”（Value）。问题和标签越匹配，就从那个词那里拿越多信息，加到自己身上。于是“苹果”看到“手机”，就往科技那边挪。

## 节拍与字幕规则（半拍感）

- **网格按 140 BPM 记小节**：一小节 = 240 / 140 ≈ 1.7143 秒；第 n 小节起点 = (n − 1) × 240 / 140 秒。ACE 生成也用 140 BPM。
- **按 70 BPM 半拍感写词**（规划 2.2）：一个“半拍小节” = 2 个 140 BPM 小节 ≈ 3.43 秒。主歌、副歌、尾声每句占 **4 个 140 BPM 小节 = 2 个半拍小节 ≈ 6.86 秒**；桥段每句 8 小节 ≈ 13.71 秒。
- 字幕密度（2.2 节红线：半拍小节每个 9–12 字）：全部歌词每个半拍小节都不超过 12 字（阅读量按 2.2 规则计，英文短词计 1、长词计 2）；最快一句约 2.8 字/秒，远低于 4.6 字/秒的上限（`common/beat.py` 自动校验，本集无超速句）。
- 总长 204 小节 = 102 个半拍小节 = 5:49.7；按规划 2.1，慢感的集去掉第二段器乐间奏，本集要点放在尾声。
- 字幕**在小节线上切换，不做提前量**；ASS 起止取整到帧（30 fps），与动画同一套帧网格。成片帧数 = round(349.714 × 30) = **10491 帧**，构建脚本逐帧核对。

## 画面设计说明

- **常驻元素**：左上角段落提示；右上角旋钮计数器（“6.2 亿” → 主歌二第 55 小节变成“586 亿”，下方小字说明“嵌入表 6.2 亿 + GPT-3 全部注意力层的矩阵约 580 亿”）。
- **例句切分**：“小明 / 把 / 苹果 / 递给 / 了 / 妹妹 / ， / 因为 / 她 / 饿 / 了”为示意切分。
- **分数与权重**：“她”对前面 9 个 token（含自己）的示意点积分数为 +1.4、−0.6、+0.5、0.0、−0.8、+3.0、−1.0、−0.2、+0.8；softmax 后约为 0.13、0.02、0.05、0.03、0.01、0.64、0.01、0.03、0.07（“妹妹”0.64）。都是示意数值。
- **标签牌文字**（男孩·人、水果、动作、女孩·人、原因）是帮助理解的比喻；画面在第 73 小节注明：“提问 / 标签 / 内容只是比喻，q、k、v 都是向量乘上学出来的矩阵，具体含义不由人规定”。
- **注意力矩阵**（间奏、主歌三）：行 = 谁在看，列 = 被看的词，越亮权重越大；数值为随机示意，只把“她 → 妹妹”等几处设得较亮。掩码版本右上三角为灰色。
- **“她”的更新**：向量条颜色为示意；实际是加权求和的结果再乘输出矩阵，经残差连接加回（残差在第 07 集讲）。
- **桥段“苹果”漂移**：与第 05 集同样的“食物 / 科技”两团示意图，“手机”传来的 Value 把“苹果”的点推向科技团。
- **多头**：头 A（紫）她 → 妹妹 / 小明；头 B（青）递给 → 小明 / 苹果 / 妹妹；头 C（橙）每个词 → 前一个词。都是示意的“像在做什么”。
- **注意力小图墙**：24 张 10 × 10 的示意小图，其中几张是规整的对角线 / 前一个词模式，其余是随机模式，示意“很多头看不出规律”。

| 3 | “提问 / 标签 / 内容”只是比喻 | 正确的处理方式：Q、K、V 是学出来的线性变换，含义不由人规定；画面已注明（规划红线） | 同上 |
